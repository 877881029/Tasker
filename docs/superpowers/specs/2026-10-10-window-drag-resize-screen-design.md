# 窗口拖拽、缩放与屏幕自适应（2026-10-10）

状态：已获用户批准（会话内确认"按这个方案做"）。

## 问题

1. 所有几何计算使用 `primaryScreen()`：副屏、分辨率/DPI 变化、拔插显示器时展开错位、跑出屏幕、圆角判断错误。
2. 展开详情只向左长；列表贴屏幕左缘时详情被挤成 0 宽。
3. 详情标题栏/底栏空白处不能拖动窗口。
4. 圆角用多边形 `setMask`：锯齿、角落黑像素、缩放时闪；展开后无详情最小宽度。
5. 没有最大化/还原。

## 设计

- **当前屏幕**：`_screen()` 取窗口中心所在屏（回退 `self.screen()`、主屏）。展开、布局、圆角均用其 `availableGeometry()`。
- **自动收回**：监听 `screenAdded/screenRemoved`、各屏 `availableGeometryChanged`、窗口 `screenChanged`，调用纯函数 `fit_into(geo, avail)`（超大先缩，再平移进可见区）。
- **展开**：`expand_from_dock(collapsed, extra, avail, min_detail=360)` 结果始终在工作区内；左侧空间不足时整窗右移，宽度不足时压缩详情但不低于最小值（工作区更窄时以工作区为界）。程序摆放期间不覆盖"收起后位置"，收起回到展开前的位置；用户在展开状态下移动/缩放才更新。展开态最小宽度 = 列表宽 + 1 + 360。
- **拖拽区**：`MOVE_NAMES` 增加 `detail`、`detailFooter`、`journal` 外框空白（不含标题输入、胶囊、删除、日志正文）。
- **双击拖拽区**：在"铺满当前屏工作区"和"还原"之间切换；铺满时直角。不新增快捷键。
- **圆角**：删除 `setMask` 与 `round_window_mask`；顶层透明窗口上加 `CornerOverlay`（鼠标穿透、最上层），用抗锯齿路径清除圆角外像素并画 1px 边框；铺满时不裁切。
- **分隔线**：`notch` 改为 7px 命中区（中间 1px `LINE` 线，左 `PAPER` 右 `CHROME`），`SplitHCursor`；拖动调整列表宽度（列表 ≥ 280，详情 ≥ 360），窗口总宽不变；宽度在本次运行内记住（收起后列表保持该宽度）。

## 不变

功能、快捷键、数据格式、托盘、单实例、主题色板与公开接口不变。
